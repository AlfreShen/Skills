# arch-diagram

給人讀的說明。模型照 `SKILL.md` 做事，不讀這份。

## 使用場景

- 使用者要一張架構圖、系統圖、管線圖、元件圖或資料流程圖，或要一個 `.drawio` 檔
- 要更新或重畫既有的那一張
- 使用者要說明系統各部分怎麼連接，即使沒提 draw.io 或架構

## 功能

- 畫出使用者可以繼續在 draw.io 編輯的圖
- 有舊版（`.drawio`、PNG、產生器腳本）就以舊版為底，只改錯的地方與使用者要求的地方
- 開工前先問清楚哪個檔是權威：產生器腳本，或手改過的 `.drawio`
- 先用一句話寫下這張圖要回答的問題與讀者，再決定每個元素的層級；元素逐一過刪除測試，圖範圍外的工具與測試設施另放
- 動筆前對照程式碼查證：每條線上實際流動的欄位、每個輸出有沒有人讀、哪些路徑常開、哪些有條件
- 結構用元件與資料儲存表示，線只表示資料流向，由產出者指向使用者；有條件的路徑用虛線
- 每個部分的邊界上有埠，線只從埠進出，且垂直接上邊界；線不穿過部分或標題
- 預設不上色；只有某個維度值得一眼看出時才上色，最多兩個維度，各有自己的圖例列
- 每條線標明所載的資料內容，用名詞片語列出欄位，不用訊息類型、路徑、函式名稱或動詞
- 圖例每個編碼維度一列，各列共用同一組欄位
- 附有產生器腳本 `drawio_gen.py`，可畫出符合上述規則的圖，並提供結構檢查（端點、埠、重複編號、重疊）
- 交付前先用程式檢查，再用 draw.io 命令列轉成圖片逐頁檢視
- 交付時附說明，列出簡化或省略了什麼、強制交叉的位置、省略的標籤、沒能做的檢查

## 不處理的事

- 投影片本身的結構與文字：`slides`（圖放進簡報時，簡報歸 `slides`，圖怎麼畫歸這個 skill）
- 時序圖：這個 skill 的圖沒有時間軸；順序重要時只提議改畫時序圖
- 給完全不懂的人看的單頁說明：`eli5`

## 需要的工具

- 能執行程式碼，並有 Python 3.6 以上
- draw.io 桌面版或命令列，用來轉圖檢視；沒有時要先問使用者是否安裝，裝不起來時圖仍可建出，但交付時要說明沒做轉圖檢查
- 在沒有螢幕的 Linux 上另需 xvfb

## 專案自訂的事項

- 圖上的文字語言、字型與大小、顏色代表的意思、固定的元件與欄位名稱、輸出格式、縮放與長寬比、元素數量上限、檔案放哪裡、本機 draw.io 的特殊狀況，寫在該專案自己的指示（`CLAUDE.md`、Project instructions），不寫進這份 skill
