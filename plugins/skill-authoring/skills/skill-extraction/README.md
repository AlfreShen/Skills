# skill-extraction

給人讀的說明。模型照 `SKILL.md` 做事，不讀這份。

## 使用場景

- 一段工作（排查、設計、分析、協調）經過來回修正後收斂，值得下次直接照做
- 使用者要把一套做法、工作流、偏好或原則記下來，整理成 skill 或規則文件
- 用 `skill-rules` 把一段工作流做成 skill 時，一併載入

## 功能

- 萃取的內容分兩種：做法（步驟附完成條件、踩過的坑）與偏好（某個人的品味與原則，每條附檢查問題與本人原話）；兩種同時出現時分成兩份
- 先把原料寫進紀錄檔，每條附日期與出處，只寫路徑不寫行號；對話裡的內容也要抄進來
- 逐條判斷去處：通用的做法進共用 skill；只屬於某個專案的進該專案的指示；偏好不放共用 skill：對某類工作的品味放專案的指示（到處都適用的，照使用者自己的跨專案流程處理）；回覆偏好與個人工作方式放使用者自己的設定
- 先找既有的同類 skill，決定補進去還是另開新的
- 抽象化：只寫找到答案的方法，只屬於這一次的檔名、數字、編號留在紀錄檔；共用 skill 不指向紀錄檔，避免專案的案例外流
- 決定觸發方式（模型自動叫或只能手動叫），再照 `skill-rules` 寫並跑它的審查清單
- 交給一個新開、沒看過這段對話的 agent 實際照做驗證；改到步驟或判準就再驗一輪；驗完才把草稿與紀錄檔放到定案的位置

## 不處理的事

- skill 裡放什麼、放哪裡、段落順序、能不能放例子、審查清單：`skill-rules`
- 把使用者對既有 skill 的修正折回去：`skill-rules` 第 6 節
- 正式的評測與 description 調校：交給 skill-creator 這類建 skill 的工具

## 需要的工具

- 不需要額外工具。驗證那一步要能新開一個 agent（不是複製目前這段對話的那種）

## 專案自訂的事項

- 草稿與紀錄檔放哪、紀錄檔叫什麼、專案的偏好放在哪、誰負責驗證，寫在該專案自己的指示（`CLAUDE.md`、Project instructions），不寫進這份 skill
