# slides

給人讀的說明。模型照 `SKILL.md` 做事，不讀這份。

## 使用場景

- 建立或修改用來說明的簡報：報告、簡報說明、檢討，或對系統、研究、結果的解說
- 任何工具都適用；使用 pptx 或 Claude Slides 這類工具專屬的 skill 或 artifact 類型時，也一併載入這份

## 功能

- 先確認簡報要回答的問題；與這個問題無關的內容不放
- 有既有簡報就從現行版本改起，保留使用者的修改；來源有多個版本時，先比對並列出差異
- 先在分鏡表規劃，再做投影片：每張一列，記標題、說明句、圖與編號、來源、動畫、轉場
- 標題順序測試：只讀標題就能讀出論點，最終版再測一次
- 結構：先概念與效果、後細節；總覽列出 N 項就接 N 張細節；主線結尾是結論或下一步
- 內容只寫來源支持的，不編數字，不用佔位文字；觀察與推論分開標示
- 用詞：術語、符號、指標名稱與單位全篇一致；預設用正式用語；預設投影片上不放檔名與路徑
- 說明句只有兩行：第一行是主張，第二行是支持它的機制或結果；來源另放在來源行
- 每張圖有編號與說明，並逐項核對圖與真實系統是否相符（數量、資料流、組成、狀態、圖例、文字、數字、總覽）
- 版面：預設一張約 50 字以內、字不小於 12 pt（寬 13.33 吋時）；標題、說明句、來源行、頁碼位置固定；內容不留大片空白
- 講者備註預設分三段：摘要、細節（計算與推論，標明為推論）、來源
- 動畫與轉場只用來呈現順序或因果
- 發布前依清單檢查：重讀現行版本、分鏡表、結構、依據、可見文字、說明句與來源行、圖、版面、備註、確實有改到的檔
- 使用者指出一處錯誤時，全篇找出同類的一併改

## 不處理的事

- 架構圖、資料流程圖怎麼畫：`arch-diagram`
- 給完全不懂的人看的單頁說明：`eli5`
- 簡報檔本身怎麼建、怎麼編輯：由使用的工具專屬 skill 或 artifact 類型負責；兩者對工具用法有出入時，以工具的說明為準
- 聽眾、目的、章節結構、封面與結尾等版式的固定欄位、配色、字級：由專案決定

## 需要的工具

- 一個能建立或編輯簡報的工具（例如 pptx 或 Claude Slides）
- 使用 Claude Slides 時，改檔前先讀 `references/claude-slides.md`，裡面是該工具對文字、連接線、轉場與簡報檔的限制

## 專案自訂的事項

- 聽眾與目的、語氣、章節結構、有固定欄位的投影片類型（封面、章節頁、結尾）、標題寫法、固定的區塊標題與狀態用語、範本、配色、字級、每張的字數上限與元素位置、說明句長度與風格、圖的編號方式、講者備註格式、符號慣例、分鏡表位置、來源位置與工具腳本，寫在該專案自己的指示（`CLAUDE.md`、Project instructions），不寫進這份 skill
